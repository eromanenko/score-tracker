# Backlog: Score Tracker v3.0.0

Цей документ містить ідеї та технічне бачення для майбутніх оновлень застосунку Score Tracker.

## 1. Фотографії коробок ігор (Box Covers) замість емодзі
**Опис:** Замінити текстові емодзі на головному екрані на красиві фотографії коробок настільних ігор для більш професійного та привабливого вигляду.
**Технічне бачення:**
- Додати поле `coverUrl` для кожної гри у файлі `assets/games.json` (наприклад, `./assets/covers/hadara.jpg`).
- Створити нову директорію `assets/covers/` та завантажити туди оптимізовані зображення коробок (формат WebP або стиснений JPEG) для існуючих 13 ігор.
- Оновити компонент `game-select.js`:
  - Змінити дизайн карток ігор на сітку (grid) або masonry layout, де більшу частину площі займає зображення коробки.
  - Додати fall-back на емодзі/текст, якщо зображення відсутнє.

## 2. Імпорт кастомних ігор (ZIP-архівів) на пристрої
**Опис:** Можливість додавати нові ігри через завантаження ZIP-архівів з пам'яті телефону/комп'ютера.
**Технічне бачення:**
- Додати кнопку "Імпортувати гру" (з використанням `<input type="file" accept=".zip">`) у меню налаштувань або на головному екрані.
- При виборі файлу:
  - Зчитати архів за допомогою `JSZip`.
  - Перевірити наявність та валідність `config.json` в архіві.
  - Зберегти `arrayBuffer` архіву безпосередньо в IndexedDB під ключем `bundle_{custom_id}`.
  - Зберегти метадані гри (отримані з `config.json`) у спеціальний масив `custom_games` в `localStorage`.
- **Збереження даних (Persistence):** Забезпечити логіку, за якої кастомні ігри та їх архіви в IndexedDB/localStorage не видалятимуться при зміні версії офіційного `games.json` чи оновленні кешу Service Worker.
- **Видалення:** Додати UI для видалення кастомної гри зі списку (із зачищенням відповідного файлу в IndexedDB та метаданих в `localStorage`).
- Оновити `game-select.js`, щоб він об'єднував ігри з `assets/games.json` та з локального `custom_games` перед рендером списку.

## 3. Вбудований візуальний конструктор ігор (Game Builder)
**Опис:** Інтерфейс у самому застосунку, який дозволить користувачеві самостійно створити конфігурацію нової гри (задати категорії, кольори, підписи, завантажити іконки) та зберегти її.
**Технічне бачення:**
- Створити новий компонент (наприклад, `<game-builder>`), який працюватиме як покроковий майстер (wizard).
- **Крок 1:** Основна інформація (Назва гри, ліміти гравців, тип підрахунку - category, tracker тощо).
- **Крок 2:** Налаштування категорій. Можливість додавати категорії, вибирати для них колір, завантажувати іконку з галереї пристрою, писати підказки.
- **Генерація:**
  - Перетворити всі завантажені користувачем картинки на Blob/ArrayBuffer.
  - Згенерувати JSON структуру для `config.json`.
  - Використати `JSZip` для створення ZIP-архіву прямо в оперативній пам'яті браузера.
  - Зберегти згенерований архів у IndexedDB та метадані в `custom_games`, подібно до пункту 2.
- **Експорт:** Додати кнопку для скачування створеного ZIP-архіву, щоб користувач міг поділитися своєю грою з іншими або додати її в офіційний `assets/games.json`.
